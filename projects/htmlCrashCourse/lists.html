Lists

Unordered lists

<ul>
    <li>Go</li>
    <li>JavaScript</li>
    <li>SQL</li>
</ul>

Use <ul> when the order of items doesn't carry meaning — a bullet list of skills, features, ingredients.

Ordered lists

<ol>
    <li>Clone the repo</li>
    <li>Install dependencies</li>
    <li>Run the server</li>
</ol>

Use <ol> when sequence matters — steps, rankings, anything where item 1 has to come before item 2 for it to make sense.

Nested lists

<ul>
    <li>Backend
        <ul>
            <li>Go</li>
            <li>SQL</li>
        </ul>
    </li>
    <li>Frontend
        <ul>
            <li>HTML</li>
        </ul>
    </li>
</ul>

The nested <ul> goes inside the <li> it belongs under, not after it as a sibling — that's what makes it structurally "a sublist of this item" rather than "an unrelated list that happens to come next."

Description lists

<dl>
    <dt>Go</dt>
    <dd>Used for backend services and CLI tools</dd>
    <dt>SQL</dt>
    <dd>Used for querying and modeling relational data</dd>
</dl>

<dl> (description list) pairs a term (<dt>) with its description (<dd>) — useful for a glossary, or (as here) a skill paired with how you actually use it, which is a step up from a bare bullet list of skill names.

Apply it

Add a skills section to your profile: an <h2> ("Skills") followed by a <ul> of at least five skills, with at least one skill grouped into a nested sublist by category (e.g. "Languages" containing a nested list of specific languages). If you'd rather show how you use each skill instead of just naming it, use a <dl> instead — your choice, but be able to explain why you picked the one you picked.
