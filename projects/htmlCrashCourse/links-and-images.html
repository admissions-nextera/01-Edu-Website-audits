Links and images

Links

<a href="https://github.com/yourname">My GitHub</a>

<a> (anchor) with an href attribute is the entire mechanism the web is built on. A few things worth knowing beyond the basic form: 

<a href="https://example.com" target="_blank" rel="noopener">Opens in a new tab</a>
<a href="mailto:you@example.com">Email me</a>
<a href="#contact">Jump to the contact section</a>
  • target="_blank" opens the link in a new tab. Pair it with rel="noopener" — without it, the new page gets partial JavaScript access back to your page, which is a real (if narrow) security concern.
  • href="mailto:..." opens the visitor's email client with that address pre-filled.
  • href="#id" jumps to whatever element on the same page has id="contact" — useful for in-page navigation, and something you'll use in the semantic layout chapter.

Link text matters for accessibility: "click here" tells a screen reader user nothing when they're skimming a list of links out of context. "My GitHub profile" does.

Images

<img src="profile.jpg" alt="Headshot of Jane Doe smiling">

<img> is a void element (no closing tag). Two attributes you should treat as non-optional:

  • src — where the image file is.
  • alt — a text description of the image, read aloud by screen readers and shown if the image fails to load. This isn't a caption; it's what someone who can't see the image needs to know instead.

Relative vs. absolute paths

<img src="images/profile.jpg" alt="...">      <!-- relative: next to this HTML file -->
<img src="/images/profile.jpg" alt="...">     <!-- relative to the site root -->
<img src="https://example.com/pic.jpg" alt="...">  <!-- absolute: a full URL, anywhere -->

For a project like this one that you'll hand around as a folder, relative paths (the first form) are almost always what you want — an absolute https://... path breaks the moment the image isn't hosted there anymore, and a leading-slash path assumes a specific server setup that a plain local folder doesn't have.

Apply it

Add a profile image near the top of your page (any image file works for now — even a placeholder) with a meaningful alt description, using a relative path. Then add a short list of links: your GitHub, and two or three other profiles or project links, each with descriptive link text (not "click here").
