Level up: extra features

Optional, roughly ordered from smallest to largest change. All of these stay within plain HTML — no CSS or JavaScript required, though a few naturally set up material you'd use once you learn them.

A Projects section

Add a Projects <section> where each project is its own <article> — a project name as a heading, a short description, and a link. This is the clearest real use case for <article> in this whole project: each one genuinely makes sense pulled out and shown on its own.

A second linked page

Split your profile into index.html (About + Skills) and resume.html (Experience + Contact), linked from a shared <nav> on both pages. This is your first real taste of a multi-page site, and forces you to think about which nav link should be visually/structurally marked as "current page" once you eventually add CSS.

A downloadable resume file

<a href="resume.pdf" download>Download my resume (PDF)</a>

The download attribute tells the browser to download the file rather than navigate to it. Add an actual PDF (even a placeholder) and try it.

Open Graph metadata

<meta property="og:title" content="Jane Doe &ndash; Developer Profile">
<meta property="og:description" content="...">
<meta property="og:image" content="images/profile.jpg">

These control how your page appears when linked in Slack, Twitter/X, Discord, or similar — the preview card with a title, description, and image. Add them and, if you can host the file somewhere public even temporarily, paste the link into a chat app to see the card render.

A print-friendly ordering

Reorder your sections so the page reads sensibly if someone printed it directly from the browser right now, with zero CSS: does Contact make more sense before or after Experience on a printed page someone might hand to a recruiter? This is a genuine content-structure question, separate from anything CSS's @media print would later let you control visually.

A sitemap-style footer

Expand your <footer> into a small secondary <nav> repeating your main links, plus a "last updated" line. Real sites do this constantly; it's a good excuse to practice <nav> appearing more than once in a single page (which is completely valid — a page can have multiple navigation regions).
