Semantic HTML5 layout

Everything you've built so far probably lives directly inside <body> with no outer structure. HTML5 added a set of elements specifically to describe the large-scale regions of a page, so that structure is explicit rather than implied by a pile of generic <div>s. 

<body>
    <header>
        <h1>Jane Doe</h1>
        <nav>
            <a href="#about">About</a>
            <a href="#skills">Skills</a>
            <a href="#contact">Contact</a>
        </nav>
    </header>

    <main>
        <section id="about">
            <h2>About</h2>
            <p>...</p>
        </section>

        <section id="skills">
            <h2>Skills</h2>
            <ul>...</ul>
        </section>

        <section id="contact">
            <h2>Contact</h2>
            <form>...</form>
        </section>
    </main>

    <footer>
        <p>&copy; 2026 Jane Doe</p>
    </footer>
</body>

What each region means

  • <header> — introductory content for the page (or for a section it's nested in). Not to be confused with <h1>–<h6>; a header is a region, a heading is a specific text element that usually lives inside one.
  • <nav> — a block of navigation links. Screen readers can jump straight to "the navigation landmark" without you doing anything extra.
  • <main> — the primary content of the page. There should be exactly one per page, and it should not include repeated boilerplate like the header or footer.
  • <section> — a thematic grouping of content, generally introduced by its own heading. Your "About," "Skills," and "Contact" blocks each earn their own <section>.
  • <article> — content that would make sense distributed or syndicated on its own, independent of the rest of the page (a blog post, a single project writeup). If you added a "Projects" section listing several independent projects, each project would reasonably be its own <article> inside that section.
  • <aside> — content tangentially related to the main content near it (a pull quote, a related-links box) — not the main flow, but not unrelated either.
  • <footer> — closing content for the page (or section): copyright, contact info repeated in short form, and similar.

section vs. div

The test that actually matters: would this chunk of content make sense described by its own heading, as a distinct topic? If yes, it's a <section>. If you just need a wrapper for styling or grouping with no topical meaning of its own, <div> is still the correct, honest choice — wrapping everything in <section> "to be semantic" is itself a misuse of the tag.

Apply it

Restructure your whole profile page into this layout: a <header> with your name and a <nav> linking (via #id anchors) to each section, a <main> containing an About <section>, a Skills <section>, an Experience <section> (your table), and a Contact <section> (your form), and a <footer>. Give each <section> an id that matches what your nav links point to, and click each nav link to confirm it actually jumps to the right place.
