Practical questions

Small, concrete tasks against your finished page. Each should take minutes, not hours.

  1. Delete the closing </li> from one item in your skills list (leave the opening tag) and reload the page. Does it visibly break? What does that tell you about how forgiving browsers are with malformed HTML — and why that forgiveness is a double-edged thing to rely on?
  2. Run your page through the W3C Markup Validator on purpose with that broken tag still in place. Compare what the validator flags versus what the browser actually did about it silently.
  3. Change one of your <label for="..."> values so it no longer matches its input's id. Click directly on that label text. Does focus still jump to the input? What did you just prove about the label/input relationship?
  4. Temporarily remove the alt attribute from your profile image entirely (not just make it empty — delete the attribute). Reload and try to figure out, using only your browser's built-in tools, what a screen reader would announce for that image now versus before.
  5. Add a second, completely separate page — projects.html — and link to it from your nav using a real relative link (not a # anchor). Confirm clicking it in the browser actually navigates there and the back button returns you to your profile.
  6. Count how many elements in your finished page are void elements (no closing tag). List them. Explain, for just one of them, why HTML doesn't require (or allow) a closing tag for it.
  7. Give two different <section> elements on your page the exact same id value on purpose. Click a nav link that targets that id. Which section does the browser actually jump to? Then run the validator again and read what it says about it.
