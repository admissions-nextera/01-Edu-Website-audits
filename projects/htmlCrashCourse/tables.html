Tables

<table>
    <thead>
        <tr>
            <th>Role</th>
            <th>Company</th>
            <th>Years</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Tech Lead</td>
            <td>01EDU</td>
            <td>2024&ndash;present</td>
        </tr>
    </tbody>
</table>

The pieces

  • <table> wraps the whole thing.
  • <thead> groups the header row(s); <tbody> groups the data rows. Both are optional structurally but recommended — they let a screen reader announce "you're in the header row" versus "you're in row 3 of the data," and they give you something to target if you ever add CSS.
  • <tr> is a table row.
  • <th> is a header cell (bold and centered by default, and semantically marked as a header, which matters more than the styling).
  • <td> is a regular data cell.

The rule that matters most: don't use tables for layout

Long before CSS layout tools were standard, developers used <table> to arrange whole pages — navigation in one cell, content in another. That practice is considered a serious anti-pattern today, for a concrete reason: a screen reader announces a table as tabular data ("table with 3 columns and 5 rows..."), which is confusing and unhelpful noise when the "table" is actually your entire page layout with no tabular relationship at all. Reserve <table> for content that's genuinely rows-and-columns data — a schedule, a price list, a comparison, an experience history.

Apply it

Add an experience or education table to your profile: at minimum, columns for role/degree, organization, and dates, with two or three rows. Use <thead>/<tbody> and <th> for the header row.
