Forms

<form action="/contact" method="post">
    <label for="name">Name</label>
    <input type="text" id="name" name="name" required>

    <label for="email">Email</label>
    <input type="email" id="email" name="email" required>

    <label for="message">Message</label>
    <textarea id="message" name="message" rows="4"></textarea>

    <button type="submit">Send</button>
</form>

form: action and method

action is where the data goes when submitted; method is how (get appends the data to the URL, post sends it in the request body). For this project you have nothing running server-side to receive it yet, so a placeholder action is fine — the point right now is the markup, not a working submission.

label and for/id — not optional

<label for="name"> paired with <input id="name"> is what lets a screen reader announce "Name, edit text" when the input receives focus, and it's also what makes clicking the label text itself focus the input — try it once you've built this and click directly on a label word. An input with no associated label is a common, easy-to-miss accessibility failure; the browser won't warn you, it'll just silently work worse for anyone using assistive technology.

Input types

<input type="text">
<input type="email">
<input type="tel">
<input type="number">
<input type="checkbox">
<input type="radio" name="contact-method" value="email">
<input type="radio" name="contact-method" value="phone">

The type attribute isn't just cosmetic — type="email" gets you browser-level format validation and brings up an email-optimized keyboard on mobile, for free, with zero JavaScript. Radio buttons in the same group must share the same name — that shared name is how the browser knows they're mutually exclusive choices rather than independent checkboxes.

select and textarea

<label for="role">I'm interested in</label>
<select id="role" name="role">
    <option value="frontend">Frontend work</option>
    <option value="backend">Backend work</option>
</select>

<textarea id="message" name="message" rows="4"></textarea>

<select> is for choosing one (or, with the multiple attribute, several) from a fixed list. <textarea> is for free-form multi-line text; unlike <input>, its default content goes between the opening and closing tags, not in a value attribute.

Validation attributes

<input type="text" required minlength="2" maxlength="50">
<input type="number" min="0" max="120">

required, minlength/maxlength, and min/max give you real client-side validation with no JavaScript at all — try submitting the form you build below with a required field empty and watch the browser block it on its own.

Apply it

Add a contact form to your profile with: a labeled name field, a labeled email field (using type="email", marked required), a labeled message <textarea>, and a submit button. Every input needs a properly associated <label> — no exceptions.
