Testing your server

With the server running in one terminal, run these from another.

Check the starting state

curl http://localhost:8080/current
curl http://localhost:8080/history

Expect the starting URL you picked (e.g. "home"), with both stacks empty.

Visit a few pages

curl -X POST http://localhost:8080/visit -d '{"url":"a"}'
curl -X POST http://localhost:8080/visit -d '{"url":"b"}'
curl -X POST http://localhost:8080/visit -d '{"url":"c"}'
curl http://localhost:8080/history

Expect current to be "c", back to contain ["home", "a", "b"] (or in whatever order you chose to represent "top of stack"), and forward empty.

Go back twice

curl -X POST http://localhost:8080/back
curl -X POST http://localhost:8080/back
curl http://localhost:8080/current

Expect current to now be "a".

Go forward once

curl -X POST http://localhost:8080/forward
curl http://localhost:8080/current

Expect current to be "b" again.

Branch off — the important case

curl -X POST http://localhost:8080/visit -d '{"url":"d"}'
curl -X POST http://localhost:8080/forward

The second call here should fail. Visiting "d" from "b" should have wiped out the forward stack (which had "c" in it), since you branched off into new history. If this call succeeds instead of erroring, go back to Visit in history.go — the forward-clearing step is missing or in the wrong place.

Exhaust the back stack

curl -X POST http://localhost:8080/back
curl -X POST http://localhost:8080/back
curl -X POST http://localhost:8080/back
curl -X POST http://localhost:8080/back

At some point you'll run out of back-history. Confirm you get your chosen error status back, not a panic and not a 200 with a nonsense value.
