Stack refresher

A stack is a LIFO (last in, first out) structure with two core operations:

  • Push — add an item to the top.
  • Pop — remove and return the item on top.

Most implementations also add a non-destructive Peek (look at the top item without removing it) and an IsEmpty check, since popping an empty stack is undefined behavior you need to guard against explicitly.

In Go, a stack is commonly built on a slice, since a slice already gives you an efficient, growable, contiguous backing array: 

type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(item T) {
    s.items = append(s.items, item)
}

func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 {
        return zero, false
    }
    last := len(s.items) - 1
    item := s.items[last]
    s.items = s.items[:last]
    return item, true
}

func (s *Stack[T]) Peek() (T, bool) {
    var zero T
    if len(s.items) == 0 {
        return zero, false
    }
    return s.items[len(s.items)-1], true
}

func (s *Stack[T]) IsEmpty() bool {
    return len(s.items) == 0
}

This is a generic stack ([T any]), so it works for a stack of strings, structs, whatever you need. You're free to use this shape directly in the project, adapt it, or write your own from scratch — the important part is that Push/Pop/Peek all behave correctly at the boundaries (empty stack), since that's exactly where the browser-history bugs will hide.

One detail worth internalizing now, because it matters directly for this project: popping from an empty stack should never panic or silently return garbage. It needs to be a signal you can check for (ok bool, an error, whatever convention you pick) — because "the user hits Back with no history to go back to" is not an edge case you get to ignore, it's the very first thing a real user will try.
