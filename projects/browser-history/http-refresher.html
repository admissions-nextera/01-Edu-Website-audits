HTTP server refresher

The pieces from last session's HTTP material that you'll actually use here:

A handler is just a function

func currentHandler(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("hello"))
}

Every handler gets an http.ResponseWriter to write the response to, and an *http.Request describing what came in (method, path, body, headers).

Routing with net/http's ServeMux

mux := http.NewServeMux()
mux.HandleFunc("POST /visit", visitHandler)
mux.HandleFunc("POST /back", backHandler)
mux.HandleFunc("POST /forward", forwardHandler)
mux.HandleFunc("GET /current", currentHandler)

http.ListenAndServe(":8080", mux)

The "METHOD /path" pattern syntax (method-aware routing) is available in the standard library's ServeMux since Go 1.22. If you're on an older Go version, you'd instead register on the bare path and check r.Method yourself inside the handler.

Reading a JSON request body

type visitRequest struct {
    URL string `json:"url"`
}

func visitHandler(w http.ResponseWriter, r *http.Request) {
    var req visitRequest
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, "invalid request body", http.StatusBadRequest)
        return
    }
    // ... use req.URL
}

Writing a JSON response

func writeJSON(w http.ResponseWriter, status int, data any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(data)
}

Status codes you'll actually need here

  • 200 OK — the operation succeeded.
  • 400 Bad Request — the request body was malformed or missing required fields.
  • 409 Conflict or 422 Unprocessable Entity — a reasonable choice for "you asked to go Back but there's nothing behind you" (the spec chapter leaves the exact choice, and the reasoning behind it, to you).

That's the full toolkit. Everything else in this project is about what happens inside those handlers — which is where the stack logic lives.
