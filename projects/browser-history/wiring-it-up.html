Step 3: Wire it up and run it

main.go was given to you in full in the starter chapter — you shouldn't need to change it unless you renamed something. Double check the three files agree with each other:

  • The method signatures on History in history.go match what handlers.go is calling.
  • The handler function names in handlers.go match what main.go registers on the mux.
  • Every file starts with package main.

Running it

go run .

You should see listening on :8080 printed, and the process should keep running (it's a server — it doesn't exit on its own).

If it won't compile

Go's compiler errors for this kind of project are almost always one of:

  • A method receiver type mismatch (*History vs History — pick one and be consistent, pointer receivers are the right call here since you're mutating shared state).
  • An unused import (Go treats this as a compile error, not a warning).
  • A TODO stub that still returns the zero-value placeholders from the scaffold, causing a downstream type mismatch once you start actually using the return values.
