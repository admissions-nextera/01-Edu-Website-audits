Step 1: Build the History type

Work through history.go method by method. Don't move on to the handlers until these pass your own manual testing (write a quick main that calls them directly, or a real _test.go if you're comfortable with Go's testing package).

Visit

Three things happen, in this order — get the order right:

  1. The current URL (before this visit) gets pushed onto the back stack.
  2. The current URL becomes the one passed in.
  3. The forward stack is cleared.

Ask yourself: what would break if you cleared the forward stack before pushing to back instead of after? (Nothing, actually — but what would break if you updated current before pushing the old value to back? Trace through it.)

Back

Guard the empty case first, before touching anything:

  • If back is empty, return "", false immediately.
  • Otherwise: the current URL needs to go somewhere before you overwrite it — where?
  • Pop the top of back. That popped value becomes the new current.

This is the operation where a subtle bug is easy to introduce: forgetting to save the current URL onto forward before overwriting it. If you skip that step, Forward() will have nothing to work with even though the user clearly has somewhere to go forward to.

Forward

This should look like a mirror image of Back, with back and forward swapped. If your Back and Forward implementations don't look like near-mirrors of each other, that's worth pausing on — it usually means one of them has a bug the other doesn't.

Current and Snapshot

Straightforward reads. The only thing worth thinking about: should these also take the mutex lock? (Yes — see the concurrency requirement in the spec chapter. A read racing with a concurrent write is still a race.)

The mutex

Every method that touches h.back, h.current, or h.forward — reads included — needs to hold h.mu for the duration. The standard pattern: 

func (h *History) Visit(url string) {
    h.mu.Lock()
    defer h.mu.Unlock()
    // ...
}

Using defer for the unlock means you can't forget to release the lock on an early return, which matters a lot here since Back/Forward both have an early-return path for the empty-stack case.

Self-check before moving on

Trace through this sequence by hand and write down what Current() should return after each step, before you test it in code: 

Visit("a")
Visit("b")
Visit("c")
Back()
Back()
Visit("d")
Forward()

(The last Forward() call should fail — work out why before you run it.)
